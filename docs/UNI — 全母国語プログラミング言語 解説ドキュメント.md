# UNI — 全母国語プログラミング言語 解説ドキュメント

**文法コアv0.4 準拠(2026-08-09 時点)**

---

## 1. UNIとは

UNIは、母国語でプログラミングでき、コンパイル(トランスパイル)によって既存のプログラミング言語に変換される言語である。

名前の由来: **universal**(全母国語)の頭3文字。日本語音では「うに」として一語で立つ。名前自体が二面投影になっている。

### 一言でいうと

> 中立ASTを核に、**入力側は各自然言語**、**出力側は各プログラミング言語**へ投影される、二面投影型の言語。

```
[各自然言語ソース] ←投影← [中立AST(核)] →投影→ [各プログラミング言語]
 日本語/英語/…                              Python/PHP/Java/JS
```

- 日本語で書いたプログラムは、対応表を差し替えるだけで英語ソースとしても読み書きできる(実証済)
- 変換先の言語(Python等)と互換なので、変換先のライブラリ・エコシステムをそのまま利用できる

### v1 ターゲット言語

**Python / JavaScript / PHP / Java**(全てGCあり・例外ベースでランタイム意味論が近く、同時対応が成立する)

## 2. 五つの特徴

### 特徴① IMEフリー原則 — 入力モードを一度も切り替えない

日本語入力モードのまま、すべてのコードが打てる。

- キーワードは**全角大文字英字**(`FOR` `IF` `ELSE`)— 日本語モードのまま打てる
- 記号も全角(`＝` `、` `。` `’` `「` `￥`)— すべて日本語キーボードで一打
- **全角/半角・大文字/小文字は正規化して同一視**(`FOR`＝`FOR`＝`for`、`１０`＝`10`)。打ちやすい方で打てばよい

既存のあらゆる言語が日本人に強いてきた「記号のたびに半角へ、コメントのたびに全角へ」という往復が存在しない。

### 特徴② 字種判定文法 — 一文字目だけで品詞が確定する

| 一文字目 | 種別 |
|---|---|
| `「` | 変数 |
| `￥` | 役割修飾子(引数宣言) |
| ひらがな列 | 関数 |
| 全角大文字英字 | 制御キーワード |
| 数字 | 数値リテラル |
| `’` | 文字列リテラル |
| `＝` `、` `。` | 演算子/区切り/終端 |

パーサは先読みなしで全トークンを分類でき、人間の目もカラースキームなしで同じ判定ができる。**ソースの見た目自体が構文情報を運ぶ**。

### 特徴③ 閉じない構文 — 閉じ忘れバグが原理的に存在しない

- `「りんご` — 変数シジルは閉じない(PHPの`$`と同じ)
- `{` — 閉じ`}`は省略可(インデントで自動クローズ)
- 関数呼び出しに括弧を使わない(`りんごをたす、5。`)— 開き括弧も閉じ括弧もない
- 文字列`’〜’`のみ明示閉じ(文中に`。`を含めるため)

「人間は閉じ忘れる」を前提にした寛容設計。

### 特徴④ 語順自由スロット文法 — 全母国語化の心臓部

マーカー(`から` `まで` `ずつ`…)が語の役割を担い、**位置は意味を持たない**。

```
FOR 1 「Iが3まで 1ずつふえる
FOR 「Iが 1 3まで 1ずつふえる
FOR 1ずつふえる 「Iが 1 3まで
```

すべて同じ意味。この設計により、SOV(日本語)/SVO(英語)の語順差、後置マーカー(`3まで`)/前置マーカー(`to 3`)の差が**スロット構造の手前で吸収される**。各自然言語の追加は、マーカー表+動詞表という対応表(約20行)の差し替えだけで済む。

### 特徴⑤ 透過3層モデル — 「すべてのメリット吸収」の構造

UNIは統一意味論に全機能を詰めない。変換先との互換により、ターゲットのメリットを**透過**する。

1. **ライブラリ層**(numpy等が使える)— 互換だけで透過。安い
2. **ランタイム層**(GC・並行モデル)— 生成コードのスタイルで決まる
3. **コンパイル時意味論層**(借用検査等)— 注釈系が必要。v2以降(Rust/C追加時)の課題

## 3. 文法リファレンス

### 3.1 シジル・役割修飾子

| 記号 | 意味 | 例 | 備考 |
|---|---|---|---|
| `「` | 変数シジル | `「りんご` | PHPの`$`相当。閉じ不要。変数名に「の」等を含められる(`「りんごの数`) |
| `￥` | 仮引数マーカー | `￥「数` | `「`の前に重ねる合成形。定義行のみに現れ、本文では`「数`で参照 |

構造: `「`が実体(変数である)を示し、`￥`が属性(引数という役割)を示す。実体マークと属性マークが直交して合成できる体系。将来、定数・参照渡し等の役割修飾子を同じ位置に追加できる。

### 3.2 マーカー表

| マーカー | 意味 | 例 |
|---|---|---|
| `から` | 初期値/開始値 | `「りんご0から` / `FOR 1から` |
| `まで` | 終値 | `3まで` / `「上限まで`(変数も可) |
| `ずつ` | 刻み | `1ずつ` |
| `が` | ループ変数指定 | `「Iが` |
| `より大きい` | `>` | `「りんご10より大きい` |
| `より小さい` | `<` | |
| `以上` / `以下` | `>=` / `<=` | (想定・実装未) |

`から`はforの開始値と変数初期化で同じ意味を持つ——「〜から始まる」という一つの概念が文脈を問わず同じマーカーで通る。

### 3.3 動詞表

| 動詞 | 意味 | 例 |
|---|---|---|
| `足す` | `+=` | `1足す`(暗黙対象) / `「りんご 「数 足す`(明示対象) |
| `ふえる` / `へる` | ループ方向(昇順/降順) | `1ずつふえる` |
| `渡す` | `return` | `最後に「りんご渡す`(「最後に」は修飾) |
| `出す` | 出力(`print`等) | `’こんにちは’ 出す。` |

演算の暗黙対象 = 直前に導入した変数。明示があれば明示を優先。

### 3.4 キーワード

| キーワード | 意味 | 表記 |
|---|---|---|
| `FOR` | ループ | 英名・全角大文字(正規化で表記ゆれ吸収) |
| `IF` / `ELSE` | 条件分岐 | 同上 |
| `定義` | 関数定義 | **日本語**。この言語で最も書く行為だから母語の動詞で始まる |

制御構造は英語キーワード(世界共通の骨)、データと演算は日本語(肉)、という配分。

### 3.5 リテラル・演算子・区切り

| 要素 | 意味 | 例 |
|---|---|---|
| `’〜’` | 文字列リテラル(明示閉じ) | `’こんにちは’` |
| 数字 | 数値リテラル(全角可・助数詞なし) | `10` / `１０` |
| `＝` | 代入 | `「りんごの数 ＝ りんごをたす、5。` |
| `、` | 引数区切り(括弧不使用) | `関数名、引数1、引数2` |
| `。` | 文終端(`;`相当。改行でも閉じる) | |

## 4. 構文解説

### 4.1 変数

```
「りんご            … 宣言(0/空で自動初期化)
「りんご0から       … 初期値つき宣言
「りんごの数 ＝ 5。 … 代入
```

初出の変数は宣言+ゼロ初期化。Java投影でも辻褄が合う。

### 4.2 出力(Hello World)

```
’こんにちは’ 出す。
```

| ターゲット | 生成コード |
|---|---|
| Python | `print("こんにちは")` |
| JavaScript | `console.log("こんにちは")` |
| PHP | `echo "こんにちは";` |
| Java | `System.out.println("こんにちは");` |

4言語の出力は関数/文/メソッドとバラバラだが、UNI側は**値+出す**の一形式で覆う。動詞表が抽象化層として機能する。

### 4.3 条件分岐

```
IF 「りんご10より大きい {
  「りんご1足す
ELSE {
  ’ちいさい’ 出す。
```

### 4.4 ループ

```
FOR 1 「Iが3まで 1ずつふえる {
  「合計 「I 足す
```

開始値・ループ変数・終値・刻み・方向の5スロット。語順自由。降順は`へる`。

### 4.5 関数

**定義**(関数名はひらがな・不可分の一語):

```
定義 りんごをたす ￥「数 {
  「りんご 0 から
  「りんご 「数 足す
  最後に「りんご渡す
```

**呼び出し**(括弧なし・`、`区切り):

```
「りんごの数 ＝ りんごをたす、5。
```

PHP投影:

```php
function plusApple($kazu) {
    $ringo = 0;
    $ringo += $kazu;
    return $ringo;
}
$apple = plusApple(5);
```

### 4.6 総合サンプル

```
定義 ごうけいする ￥「上限 {
  「合計 0 から
  FOR 1 「Iが「上限まで 1ずつふえる {
    「合計 「I 足す
  IF 「合計 10より大きい {
    ’おおきい’ 出す。
  ELSE {
    ’ちいさい’ 出す。
  最後に「合計渡す

「答え ＝ ごうけいする、5。
「答え 出す。
```

Python投影(実際のtranspiler.py出力):

```python
def ごうけいする(上限):
    合計 = 0
    for I in range(1, 上限+1, 1):
        合計 += I
    if 合計 > 10:
        print("おおきい")
    else:
        print("ちいさい")
    return 合計
答え = ごうけいする(5)
print(答え)
```

実行結果: `おおきい` `15`

## 5. 多言語対応 — 英語フロントエンドの実例

英語対応表(抜粋):

| UNI日本語 | UNI英語 | 備考 |
|---|---|---|
| `「x` | `$x` | シジルも対応表項目 |
| `￥「x` | `\$x` | `\`⇔`￥`はJIS/ASCIIで同一コード点(0x5C)の史実的対応 |
| `’〜’` | `'〜'` | |
| `0から` | `from 0` | 後置⇔前置の位置反転はマーカー1個につき規則1行 |
| `3まで` | `to 3` | |
| `1ずつ` | `by 1` | |
| `「Iが` | `as $I` | |
| `10より大きい` | `above 10` | |
| `足す` | `add` | |
| `渡す` | `give` | |
| `出す` | `show` | |
| `ふえる`/`へる` | `up`/`down` | |
| `最後に` | `finally` | |
| `定義` | `define` | |
| `。` | `.` | |
| `、` | `,` | |

同一プログラムの英語ソース:

```
define sum \$limit {
  $total from 0
  FOR from 1 as $I to $limit by 1 up {
    $total add $I
  IF $total above 10 {
    show 'big'.
  ELSE {
    show 'small'.
  finally give $total

$answer = sum, 5.
show $answer.
```

**検証結果**: 日英の生成Pythonは識別子正規化diffで**構造完全一致**。パーサ本体は1行も変更していない。対応表は約20行の辞書のみ。

## 6. v0.3〜v0.4 追加仕様

### 制御・演算
| 構文 | 意味 |
|---|---|
| `WHILE 条件 {` | 条件ループ(IFと同じ条件式) |
| `ELSE IF 条件 {` | 分岐連鎖(elif) |
| `BREAK` / `CONTINUE` | ループ脱出/スキップ |
| `TRY {` / `CATCH {` | 例外捕捉(発生条件のターゲット差は層2の性質として残る) |
| `かつ` / `または` / `〜でない` | 論理AND/OR/NOT |
| `引く` `掛ける` `割る` | -= *= /= |
| `以上` `以下` `と同じ` `とちがう` | >= <= == != |
| 負数`−5`・小数`1.5` | 全角半角とも可 |
| `「Xに5足す` | 演算対象の明示形(暗黙対象と併用可) |

### コメント
`・・`(または`//`)から行末まで。JIS配列で`・`は`/`キーの日本語モード側——`//`と物理的に同じキー操作。

### コレクション(LL体系)
- `LL`は共用かっこ: `；`(キー；値)の有無でリスト/辞書が分岐
- リスト: `「くだもの ＝ LL ’りんご’、’みかん’。` 辞書: `「じしょ ＝ LL くだもの；りんご。`
- LL内の裸語は文字列扱い(データ側の世界)。`ヌル`=null
- 番地: リスト=`N個目`(つ目/番目同一視・1始まり) 辞書=キー
- 読み `「じしょ きかい` / 追加 `足す`(=append) / 置換 `かえる` / 削除 `消す 左`(詰める)・`消す ヌル`(穴を残す) / 反復 `FOR 「リスト から 「実が {`(`2ずつ`=飛ばし読み、変数省略時=`「それ`)

### 文字列補間・入出力
- 補間: `’こんにちは「なまえ」さん’` — `」`が初めて仕事を得た(補間の閉じ)
- 入力: `「なまえ ＝ きく。` → input()/fgets/readFileSync/Scanner

### ターゲット互換層(二層)
1. **組み込み動詞層**(移植可能): `ながさ` `へいほうこん` `きく`——各バックエンドが慣用句表を持つ。Python版はimport自動挿入
2. **EX層**(ターゲット固定): `EX’time.time’、引数`でネイティブ生呼び出し。全ライブラリへの脱出ハッチ

### モジュール
`USE ’lib.uni’。` — パース前テキスト取込。

### エラー報告の母国語化
行番号つき母国語エラー(`--lang=ja|en`)。メッセージ表自体が対応表方式。
```
【2行目】FOR文には「(リスト)から」か「(終値)まで」のどちらかが必要です
```

### 識別子の英名自動変換(--names=native|romaji|en)
助詞分割→語彙対応表→ローマ字フォールバック→ターゲット規約ケース(snake/camel)→予約語回避。
`「りんごの数 ＝ りんごをたす、5。` → PHP `$appleCount = addApple(5);`(`を`は動詞先行に語順反転)

## 8. 設計思想の背景 — なぜこの形なのか

**なでしこ(既存の日本語プログラミング言語)が産業で流行らなかった構造的理由**と、UNIの対応:

| なでしこの敗因 | UNIの対応 |
|---|---|
| エコシステムの孤立(ライブラリが使えない) | 変換先と互換 — ターゲットのエコシステムを透過利用 |
| 助詞文法の学習コスト(正しい助詞の厳密運用) | 助詞体系を持たない。マーカーは最小限のスロット標識のみ |
| キャリア価値ゼロ(成果物が市場で通用しない) | 成果物はPython/PHP/Java等のコードとして残る |
| 「日本語PG=おもちゃ」の先入観 | 本質を「全母国語言語」に再定義 — 棚ごと変わる |

先行例との関係: 多言語化の原理はScratch(ブロックの70言語超ローカライズ)が教育で実証済み。**テキストベースの汎用言語+実用言語群への変換**でこれを行った例は確認されていない。
